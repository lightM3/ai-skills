# Flutter 3.38 (Nov 2025) — UIScene lifecycle on iOS

Source: https://docs.flutter.dev/release/breaking-changes/uiscenedelegate

**Why it matters now:** apps built with **Xcode 27 / iOS 27 SDK** that have not adopted
UIScene **crash on launch**. Since Flutter 3.41 UIScene is the default and the CLI
(`flutter run` / `flutter build ios`) auto-migrates **unmodified** AppDelegates and prints
`Finished migration to UIScene lifecycle`. A customized AppDelegate needs the manual steps.

## AppDelegate

```swift
@main
@objc class AppDelegate: FlutterAppDelegate, FlutterImplicitEngineDelegate {
  override func application(
    _ application: UIApplication,
    didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
  ) -> Bool {
    // No plugin registration and no FlutterViewController access here any more.
    return super.application(application, didFinishLaunchingWithOptions: launchOptions)
  }

  func didInitializeImplicitFlutterEngine(_ engineBridge: FlutterImplicitEngineBridge) {
    GeneratedPluginRegistrant.register(with: engineBridge.pluginRegistry)

    // Method channels / platform views go here:
    let channel = FlutterMethodChannel(
      name: "samples.flutter.dev/battery",
      binaryMessenger: engineBridge.applicationRegistrar.messenger())
    channel.setMethodCallHandler { call, result in /* ... */ }
  }
}
```

- `window?.rootViewController as! FlutterViewController` in `didFinishLaunching` **crashes**
  under UIScene — remove it. Messenger comes from `engineBridge.applicationRegistrar.messenger()`.
- Objective-C: conform to `<FlutterImplicitEngineDelegate>`, implement
  `- (void)didInitializeImplicitFlutterEngine:(NSObject<FlutterImplicitEngineBridge>*)engineBridge`,
  register with `engineBridge.pluginRegistry`.
- UI lifecycle callbacks (`applicationDidBecomeActive`, …) are no longer called → move them
  to a `SceneDelegate` that **subclasses `FlutterSceneDelegate`** (or conforms to
  `FlutterSceneLifeCycleProvider` and forwards to a `FlutterPluginSceneLifeCycleDelegate`).
- Need the FlutterViewController itself (not for channels)? Subclass it and use
  `awakeFromNib`, or do it in `scene(_:willConnectTo:options:)`.

## Info.plist

```xml
<key>UIApplicationSceneManifest</key>
<dict>
  <key>UIApplicationSupportsMultipleScenes</key>
  <false/>
  <key>UISceneConfigurations</key>
  <dict>
    <key>UIWindowSceneSessionRoleApplication</key>
    <array>
      <dict>
        <key>UISceneClassName</key>
        <string>UIWindowScene</string>
        <key>UISceneDelegateClassName</key>
        <string>FlutterSceneDelegate</string>
        <key>UISceneConfigurationName</key>
        <string>flutter</string>
        <key>UISceneStoryboardFile</key>
        <string>Main</string>
      </dict>
    </array>
  </dict>
</dict>
```

With a custom `SceneDelegate` (Swift) set `UISceneDelegateClassName` to
`$(PRODUCT_MODULE_NAME).SceneDelegate`.

## Plugin authors

Adopt `FlutterSceneLifeCycleDelegate`, call `registrar.addSceneDelegate(instance)` (keep
`addApplicationDelegate` for unmigrated apps), move launch logic to
`scene(_:willConnectTo:options:)` (launch options are `nil` in the app delegate now), and get
windows via `registrar.viewController?.view.window` instead of `UIApplication.shared.keyWindow` /
`delegate.window`. Requires `flutter: ">=3.38.0"`.

## Escape hatches (temporary only)

- Hide the CLI warning: `flutter: config: enable-uiscene-migration: false` in pubspec.
- Disable UIScene: prefix `Application Scene Manifest` with `_` in Info.plist. Won't launch on
  Xcode 27 builds — not a fix.
